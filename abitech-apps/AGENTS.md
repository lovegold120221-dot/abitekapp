# AGENTS.md — abitech-apps

Static app-store site, no build, no deps, no tests, no tooling. Pages: `index.html` (storefront), `liveapp-details.html` (fullscreen app preview). Shared icon module `app-icons.js`. Real PWA bundles under `apps/`, logos in `app-logos/`, hero art in `assets/`.

## Run / verify
- No install or build step. Preview with any static server, e.g. `python3 -m http.server -d .` then open `index.html`, or open the file directly.
- Requires internet: Tailwind CDN, Lucide (`unpkg.com/lucide@latest`), Google Fonts, Firebase. Page renders unstyled/broken offline.
- Verify by opening in a browser and checking console for JS errors; there is no test suite.

## Where things live
- `tailwind.config` inline in each page: `play.*` theme colors (`green`, `greenHover`, `greenLight`, etc.). Use these, not hardcoded greens.
- `LOCAL_APPS_DATA` array (in `index.html`): offline fallback catalog — the 32 real entries only: 12 bundled PWAs plus the 20 `ai-apps/` AI apps (placeholder/mock entries were deleted everywhere). Live data comes from Firebase RTDB `/apps` and replaces `APPS_DATA` at runtime. Record shape: `id, title, developer, developerEmail, category, rating, reviews, downloads, size, version, updated, requiresAndroid, contentRating, containsAds, inAppPurchases, iconBg, iconName, logoUrl, badge, description, screenshots[], featured, previewUrl`.
- Renderers: `createAppCard` / `createChartItem` / `createGridCard`, composed by `renderAppSections()` (Live Demo carousel + Top Charts) / `renderGrid()`. Cards show title + category + badge pill only — no ratings/reviews/downloads/sizes anywhere in visible UI (stored seed fields are reserved for future real values). Sections are `section-live` + `section-charts` + `section-ai` (AI Apps carousel, populated by `renderAppSections` from `category === 'AI Apps'`) + the All grid. `section-ai` shows in the `All` view only — `filterCategory`/`handleSearch` toggle it.
- `app-icons.js` (`window.AppIcons`): single source of icon artwork. `byId` pins a type-suited Lucide glyph per app id; bundled `app-logos/<id>.png` files are treated as placeholders and NOT rendered — only an external/custom `logoUrl` overlays an `<img>`. Keep `byId` in sync when adding apps.
- Interactions: `filterCategory()`, `handleSearch()` (wired to `desktopSearchInput` + `mobileSearchInput`), `openModalById()` / `closeModal()`, `simulateInstall()` (labeled "Download APK"), `openPreview()` (stashes app + catalog in `sessionStorage`, then navigates to `liveapp-details.html?id=` in the same tab). Modal tags (`#modalTags`), live-preview card (`#modalLiveIcon`), and facts strip (`#modalLiveBadge` + `#modalFacts`) are populated per app — no static mock content remains, and the modal shows no fabricated ratings/reviews/downloads.
- Firebase wiring: `firebaseConfig` + `initFirebase()` + `loadAppsFromFirebase()` (one-shot `ref('apps').once('value')`). Page renders local data first, then upgrades to live and flips `#dataSourceNote` to "Live from Firebase".
- `liveapp-details.html`: fullscreen preview — every catalog app must have `previewUrl`, enforced in `render()` (missing URL → error state). `screenHTML()` always embeds the live app in an `<iframe>`. Android/iOS/Webview toggle (`setOS()`) swaps phone frame chrome (punch-hole vs Dynamic Island, 3-button nav vs home indicator) or a browser-chrome frame (traffic dots + reload, no URL bar by request); phone/browser views live in `#phoneWrap` / `#webWrap`. `View Full App` swaps the active iframe to `externalUrl || previewUrl` without leaving the mockup, and the selected URL persists across device-mode switches. Webview mode hides the side details panel (`#detailPanel`) so the browser owns the screen. Mockup is viewport-sized (`#phoneScreen` height clamp + 9/19 aspect in CSS, which overrides the Tailwind height classes set by `osChrome()`). After any `innerHTML` injection call `lucide.createIcons()` (same rule as index).

## AI apps (`ai-apps/`)
Thirty standalone single-page apps, all in the storefront category `AI Apps` (chip labelled "AI Apps ✦"): ids `app-ai-*`, `previewUrl: 'ai-apps/<name>.html'`, registered in `LOCAL_APPS_DATA`, `firebase-seed.json` and `app-icons.js` `byId`. Three batches.

### Batch 1 — Gemini-powered (API key)
- Ten single-page apps calling the Gemini REST API directly from the browser: `dream-oracle`, `roast-my-code`, `startup-roulette`, `story-forge`, `debate-arena`, `fridge-alchemist`, `wander-weaver`, `excuse-engine`, `haiku-dojo`, `interview-sparring` (all `.html`).
- Shared pattern per file: `GEMINI_KEY` + `GEMINI_MODEL` consts, `gemini()` fetch helper to `v1beta/models/<model>:generateContent`, `esc()`/`fmt()` output helpers, button loading state + `#errorBox`. Model is `gemini-3.5-flash-lite` (verified working; `gemini-2.5-flash`/`2.5-flash-lite` return 404-retired for this key, others often 503-overloaded). Read `part.text` defensively via `.map(p => p.text || '')` — some models return thought parts without text.
- Gemini calls read a user-supplied browser key from `sessionStorage` under `abitech_gemini_key`; no API credential is stored in source. The key remains available only for the current tab, and users must create/restrict their own browser key in Google Cloud Console.
- These ARE in the store catalog as `app-ai-*` (category "AI Apps", badge "Live Demo", `previewUrl` → `ai-apps/<name>.html`, logos `app-logos/app-ai-*.png`, `byId` glyphs in `app-icons.js`) — they open live in `liveapp-details.html` like the bundled PWAs. The AI Apps chip is back in the nav.

### Batch 2 — Hugging Face models, on-device (no API key, no server)
- Ten apps in the same `AI Apps` category, badge `On-device AI`. They download real HF models and run them locally in the browser: `kokoro-voice-studio`, `supertonic-narration`, `whisper-scribe`, `sentiment-compass`, `zero-shot-sorter`, `tldr-digest`, `polyglot-desk`, `vision-lens`, `caption-canvas`, `semantic-match` (all `.html`).
- Shared pattern per file: `<script type="module">`, so every handler is wired with `addEventListener` — an inline `onclick` cannot see module scope. Each page has a status badge that flips amber "Loading…" → green "ready" (red on failure), an `esc()` output helper, a `#errorBox`, and an action button that stays `disabled` until the model resolves.
- Models: `onnx-community/Kokoro-82M-v1.0-ONNX` via `kokoro-js`; `Supertone/supertonic-3` ONNX assets via `onnxruntime-web`; and via `transformers.js` — `onnx-community/whisper-base`, `Xenova/distilbert-base-uncased-finetuned-sst-2-english`, `Xenova/mobilebert-uncased-mnli`, `Xenova/distilbart-cnn-6-6`, `Xenova/opus-mt-en-{es,fr,de,zh}` + `Xenova/opus-mt-{es,fr,de,zh}-en`, `Xenova/vit-base-patch16-224`, `Xenova/vit-gpt2-image-captioning`, `Xenova/all-MiniLM-L6-v2`.
- CDN pins: `@huggingface/transformers@4.3.0`, `kokoro-js@1.2.1`, `onnxruntime-web@1.30.0`. The Supertonic page needs an `importmap` so the archived `web/helper.js` (loaded from the jsDelivr GitHub CDN) can resolve its bare `onnxruntime-web` import; it fetches ONNX + voice-style JSON from `huggingface.co/supertone-oss-archive/supertonic-3/resolve/main/...`. Model loading tries WebGPU where offered and falls back to WASM.
- These need internet on first run (model downloads: ~90 MB for Kokoro, ~100 MB for Supertonic, ~150 MB for Whisper) then work from the browser cache. Nothing is uploaded; `whisper-scribe` needs microphone permission for live recording.

### Batch 3 — Hugging Face pipelines chained into end-to-end jobs
- Ten more `AI Apps` entries (badge `On-device AI`), same module-script pattern and CDN pin as batch 2, but each one **chains two or more models** into a task a user actually has: `meeting-notes`, `support-triage`, `subtitle-kit`, `accessible-reader`, `pii-redactor`, `answer-desk`, `listing-studio`, `voice-journal`, `contract-lens`, `review-miner` (all `.html`).
- Two model families are new here, both verified to load in-browser: `Xenova/bert-base-NER` (named-entity extraction) and `Xenova/distilbert-base-cased-distilled-squad` (extractive QA — returns the exact source sentence, which is what makes `answer-desk` and `contract-lens` quotable rather than generative).
- Chains: `meeting-notes` = whisper-base → distilbart-cnn-6-6 (+ commitment heuristics); `support-triage` = sentiment + mobilebert-mnli + distilbart, ranked by an explainable score; `subtitle-kit` = whisper-base with segment timestamps → opus-mt pair → `.srt`/`.vtt` export (timings are rebuilt from Whisper chunks, so cues stay aligned after translation); `accessible-reader` = distilbart → Kokoro-82M read-aloud; `pii-redactor` = bert-base-NER + regex patterns (emails, cards, API keys) → masked copy; `answer-desk` = MiniLM embeddings for retrieval → squad for the answer sentence; `listing-studio` = vit-gpt2 caption + vit-base classification → title/bullets/keywords; `voice-journal` = whisper-base → sentiment, entries kept in `localStorage`; `contract-lens` = NER + distilbart + squad; `review-miner` = sentiment + mnli aspects + NER for product/courier names.
- These pages never call a server and never upload input: audio, photos and documents stay in the tab. Model downloads are per-model and heavier than batch 2 (worst case `contract-lens`, three models).

## Firebase
- Project `hpanel-7a898`, RTDB `https://hpanel-7a898-default-rtdb.asia-southeast1.firebasedatabase.app`, single instance `hpanel-7a898-default-rtdb`. The database holds one top-level node, `/apps`.
- `firebase.json` + `.firebaserc` bind this repo to the project, and `firebase.json` points `database.rules` at `firebase-database.rules.json`, so that file IS the deployed ruleset — run `firebase deploy --only database` after editing it. It is no longer just a mirror.
- Live rules, verified by probe 2026-09-21: `/apps` `.read: true`, `.write: false`; every other path — including root read — returns `401 Permission denied`. Confirm anytime with `firebase database:get /.settings/rules --project hpanel-7a898` instead of trusting the repo file.
- ⚠️ Historical (avoid repeating it): until 2026-09-21 the deployed ruleset was Firebase's default test mode — `{ ".read": true, ".write": true }` at the root — so anonymous callers could read the entire database and `DELETE /.json` to wipe it. That is fixed; keep writes locked and re-check the rules if drift is ever suspected.
- Writes are locked, so updating `/apps` needs one of: Console → Realtime Database → Import `firebase-seed.json`, or temporarily set `.write: true`, `firebase deploy --only database`, PUT, then restore and redeploy the locked rules. When PUTting, send the inner object only — NOT the whole `{"apps": ...}` wrapper (that nests to `/apps/apps/`).
- `firebase-seed.json` is the source of truth for `/apps` (42 apps: 12 bundled PWAs + 30 AI apps, keyed by id).
- ⚠️ The live `/apps` node lags the repo whenever a batch is added locally and no import is run, and the store hides the difference badly: `loadAppsFromFirebase()` replaces `APPS_DATA` wholesale, so locally-added apps simply disappear once live data lands. In sync as of 2026-09-21 (42 apps / 30 AI) after a temporary flip-and-restore upload; re-import after every batch.
- Logos: bundled AI-rendered PNGs in `app-logos/<app-id>.png` (12 files, 512x512, abstract 3D object style — no robots/heads/faces per user request; OpenAI key had zero credits so they were generated with a free model instead). `LOCAL_APPS_DATA` and Firebase `/apps/<id>/logoUrl` reference them, but note `app-icons.js` treats bundled paths as placeholders and renders its Lucide artwork instead — only an external/custom `logoUrl` overlays an `<img>`. The `app-ai-*` entries follow the same convention without the files on disk: because `byId` maps the id and the path is exactly `app-logos/<id>.png`, nothing is fetched and no broken `<img>` renders. To use real image logos: upload art and set `logoUrl` to its URL.
- Hero banner: background image `assets/banner-hero.png` (AI-rendered, abstract neural waves — no robots/faces) with a dark left-to-right overlay for text legibility. To swap: replace the file, keep the same path — no code change needed.
- Store brand mark: header logo loads `https://www.abitech.site/logo.png` with an inline gradient-mark `onerror` fallback — keep the fallback if you swap the URL.

## Gotchas
- After any DOM injection you must call `lucide.createIcons()` or icons render blank. Already done in `renderAppSections`, `renderGrid`, `openModalById`, and the install-complete state — preserve this on new render paths.
- `simulateInstall()` uses `setInterval`; `closeModal()` / `resetInstallButton()` must `clearInterval(installTimer)` or timers leak across modal opens.
- Category strings are matched case-insensitively in `filterCategory`/`handleSearch` but section containers (`section-live`, `section-charts`) are hardcoded — a new category only appears in the All grid unless you add a section + wiring.
- `.squircle` = `border-radius: 22%` for app icons; keep it for visual consistency.
